# Real upstream E2E

This directory contains manual, credentialed acceptance tests. It is intentionally excluded from
the default Jest and Cargo suites.

## Layout

- `run.mjs`: starts the local release binary, verifies the upstream directly, routes adapter
  traffic through a temporary transparent probe, and optionally runs Claude Code complex text and
  Read tool scenarios. Claude is started with isolated settings so inherited user settings cannot
  replace the endpoint or model.
- `results/<UTC timestamp>-<model>.json`: sanitized summaries generated by the runner.

Schema-version-3 results may contain only model names, sanitized request shape/count fields
(including whether the request ends in an assistant prefill), HTTP
status, stream flags, chunk/event and delta-field counts, finish reasons, output-kind flags,
pass/fail flags, timing summaries, and numeric token counts. They must not contain API keys,
prompts, system or tool descriptions, schemas or arguments, file contents, full model responses,
URLs, paths, request IDs, headers, environment details, config contents, or Claude debug logs. The temporary
adapter config contains only `apiKeyEnv`; the credential itself is read from the supplied Spring
YAML into memory and passed to the native child process through that environment variable.
The temporary config also declares `assistantPrefill: native` so the matrix measures the upstream's
actual continuation behavior; it does not modify LM Studio's model configuration.

## Run

Build the native binary first:

```bash
cargo build --manifest-path native/Cargo.toml --release
```

Run against the ignored Spring local configuration:

```bash
node tests/real-e2e/run.mjs \
  --spring-config /absolute/path/to/spring-ai-test/src/main/resources/application-local.yaml \
  --with-claude
```

The runner uses the local LM Studio API at `http://127.0.0.1:1234` by default. `--upstream-root`
overrides only that server address; the API key, completions path, and model still come from
`spring.ai.openai` in the supplied YAML. Omit `--with-claude` when only the upstream and adapter
wire paths need verification. With Claude enabled, the runner executes this fixed matrix:

1. Minimal streamed text without tools.
2. The exact streamed Claude Code text request captured by the transparent probe.
3. The same Claude text request directly against LM Studio with `stream: false`.
4. A minimal streamed Read schema with `tool_choice: auto`.
5. The same Read schema with a named tool choice.
6. The complete Claude Code Read → tool result → final text loop.

The Claude text and Read scenarios require multiple separately received `text_delta` events before
the corresponding upstream response completes; Read also requires a real `Read` tool event. A
legal `content: []` / `end_turn` response is recorded as `empty_end_turn` but fails these task-level
scenarios because it did not complete the requested work. The non-stream and named-tool cases are
diagnostic and do not gate the final task result; LM Studio's documented `tool_choice` values are
`none`, `auto`, and `required`, so a rejected named function choice is recorded rather than treated
as an adapter regression.
Add `--require-thinking` to require thinking deltas in the adapter and Claude Code scenarios.

The runner creates a mode-`0600` temporary adapter config, removes it on exit, and stops the native
process gracefully. It keeps failed result files as sanitized evidence. The transparent probe
inspects responses while forwarding their bytes unchanged; captured request bodies exist only in
memory for the same-run stream/non-stream comparison and are never serialized.
